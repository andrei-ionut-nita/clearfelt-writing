# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [0.8.0] - 2026-08-24

A full-repo critique pass (every doctrine file, the scoring engine, every ADR, and the test suite, read end to end) turned up one concrete bug and a dozen structural gaps: a broken cross-reference the actual rewrite pipeline depended on, a deferred decision whose own reopening condition had silently fired and gone unaddressed, config defaults duplicated across three hand-maintained copies, three real architectural choices with no ADR behind them, and a documented parser limitation (no escaping for `|` inside a rule bullet) that forced near-duplicate rules instead of one real pattern. This release closes all of it. Not a version bump for its own sake, see `docs/RELEASE.md`'s versioning table, this is squarely Minor: a new script capability (`scripts/routing-eval.mjs`), a rule-bullet-format extension (`|` escaping), several new CI/lint guarantees, and no breaking change to any existing output shape, config key, or rule file.

### Fixed

- **A load-bearing broken reference.** `prompts/audit_loop.xml` and `prompts/write_loop.xml` cited `reference/output-format.md` six times combined; that file hasn't existed since the presentation-format split into `reference/format/*.md` (see the new `docs/decisions/0026`), and nothing had propagated the rename into the two files that actually drive the rewrite and write loops. All six citations now point at the correct `reference/format/*.md` file and section.
- **2,525 stray scratch report files** under `tests/fixtures/check/reports/` (gitignored, but bloating every local `find`/`grep` scan), accumulated because `check.mjs`'s hard-fail path writes a real timestamped file into `<cwd>/reports/` on every run, and the test suite runs it with `cwd` pointed at that exact fixture directory, with no cleanup, across every `node --test` invocation during development. Deleted the backlog; `tests/check.test.mjs` now removes the directory in an `after()` hook so it can't reaccumulate.
- **A pre-existing byte-for-byte duplicate test** in `tests/rules.test.mjs` (two identically named `corporate_neologisms` tests, same body), found while extending coverage for the rule-bullet-format change below. Removed the duplicate; the remaining test now also covers all four pronoun forms the merged bullet handles, not just one.
- **`docs/RELEASE.md`'s own prose-audit instruction silently checked one file instead of four.** `node scripts/detect.mjs --mode report SKILL.md writing.md voice.md README.md` reads `args.paths[0]` only, so every past release's step 3 audited `SKILL.md` and silently dropped `writing.md`, `voice.md`, and `README.md` from the check. Found while actually running this release's own audit. Instruction now loops one invocation per file.

### Added

- **`|`-escaping in rule bullets.** `scripts/lib/rules.mjs`'s new `splitBulletFields()` treats `\|` as a literal pipe (unescaped into the field, not a field separator) and `\\` as a literal backslash, leaving every other backslash sequence (`\w`, `\s`, `\b`, `\d`, ...) untouched. A regex bullet can now express a real alternation group instead of needing one near-duplicate bullet per alternative: `rules/antipatterns/corporate_neologisms.md`'s four pronoun-specific bullets collapsed into one, `"diligenc\w*\s+(?:it\|this\|that\|them)\b"`. `scripts/lint.mjs`'s `checkRuleBulletShape()` now fails loudly if a parsed pattern still contains a stray double-quote character, the tell-tale sign of a forgotten `\|` breaking field-splitting silently, exactly the failure mode this used to produce with no warning. `CONTRIBUTING.md` and `schemas/rule-bullet.schema.json` updated to document the new syntax instead of the old limitation.
- **A routing-judgment eval harness** (`scripts/routing-eval.mjs`, `tests/fixtures/routing/manifest.json`, 19 labeled requests, `tests/fixtures/routing/runs/`), the same shape `scripts/qualitative-eval.mjs` already established for a reasoning-only signal this dependency-free, no-API-calls repo can't judge itself: it scores recorded judgment runs against `SKILL.md`'s Routing section instead of producing a judgment on its own. Command dispatch (`docs/decisions/0019`) was the one piece of core logic with zero automated verification before this; seeded with two independent runs (the manifest's own author, and a subagent given only `SKILL.md` and no expected labels) at 19/19 and 100% pairwise agreement. Documented as `docs/decisions/notes/0001`, the first entry in the previously-empty lighter decision-record tier, since it's purely additive and doesn't change how any existing piece composes.
- **`scripts/eval.mjs --min-pass-rate <fraction>`**, and CI now passes `--min-pass-rate 0.85` (`.github/workflows/ci.yml`) instead of the previous always-exit-0 behavior. A 100% gate isn't realistic given known, disclosed recall gaps, but "can never fail" meant a real detection-quality regression, the exact shape `docs/decisions/0011` once disclosed and shipped anyway since nothing gated on it, could ship silently. 0.85 sits comfortably below the current 28/28 pass rate.
- **`docs/decisions/0025`**: percentile rescaling (deferred by `docs/decisions/0011` "until the eval corpus is grown well past 10 documents") reopened and re-deferred with a concrete, checkable reopening condition (15+ fixtures per label, per genre bucket, not just a pooled total) instead of the vague comparison that had already been silently satisfied twice (corpus grew 10 to 16 to 28) with nobody reopening the question. `scripts/eval.mjs` now prints the smallest bucket's size against this floor on every run, so the condition can't go silently unaddressed a second time.
- **A canonical "where state lives" map.** `reference/explain.md` gained a single table listing all five config/state locations (`clearfelt-writing.config.md`, `~/.clearfelt-writing/settings.md`, `.clearfelt-writing/domain.md`, `.clearfelt-writing/voice-profile.md` or `voices/<name>.md`, `.clearfelt-writing/hook-state.md`) and their precedence, previously scattered piecemeal across `reference/rewrite.md`, `reference/explain.md`'s prose, and `clearfelt-writing.config.md`. Made live, not just documented: `scripts/explain.mjs` gained a new `stateMap` field carrying the same data, and `reference/format/explain.md`'s template now presents it.
- **Three backfilled ADRs** for real architectural decisions that predated this repo's ADR discipline and had none: `docs/decisions/0026` (the `reference/<command>.md` behavior split from `reference/format/<command>.md` presentation), `docs/decisions/0027` (`scripts/lib/`'s four-module boundary: config, rules, score, report), `docs/decisions/0028` (`hook.mjs`/`pin.mjs` adapted from the `impeccable` skill, and why only those two scripts are allowed to be Claude-Code-specific). All three marked "backfilled" and cross-referenced from `docs/ARCHITECTURE.md`.
- **The "Both" multi-voice x multi-platform setup flow, fully specified.** `reference/setup.md` previously called this combination "a documented sketch... not a fully specified flow." Replaced with a concrete composition of the two already-validated flows (writer loop, then a platform loop scoped to that writer's own files), plus the naming and `--voice` CLI-resolution details that composition implies (`--voice <writer>-general`, not `--voice <writer>`, since `voiceProfilePath()` does a flat lookup with no writer-to-general shorthand).
- **A regression test locking in `movingAverageTtr`'s one real guarantee**: exact length-invariance past one window for a fixed underlying vocabulary richness, proven with a deterministic round-robin word generator, not a fuzzy "looks reasonable" check. This signal has been revised three times (`docs/decisions/0008`, `0012`, `0017`), each revision a real regression found on the next out-of-distribution document; a second test locks in the documented, intentional sub-window residual bias too, so a future "fix" that silently removes it fails a test instead of shipping unnoticed.

### Changed

- **`scripts/lib/config.mjs`'s `CONFIG_DEFAULTS` is no longer duplicated inside `scripts/lib/score.mjs`.** Ten weights and thresholds (`deduction_cap`, `burstiness_baseline`/`_weight`, `vocabulary_diversity_baseline`/`_weight`, `repetition_weight`, `paragraph_variety_baseline`/`_weight`, `wall_of_text_sentence_threshold`/`_penalty`) used to be independently hand-maintained literals in both files, kept in sync only by a lint check, and did drift once for real (`docs/decisions/0018`). `score.mjs` now imports `CONFIG_DEFAULTS` and references it directly, collapsing that copy by construction. `scripts/lint.mjs`'s `checkConfigDefaultsDrift()` narrowed to the one comparison that still needs a runtime check (`CONFIG_DEFAULTS` vs. the shipped `clearfelt-writing.config.md`, a JS object and a Markdown file with no way to share a literal); a new `checkScoreReferencesConfigDefaults()` guards against `score.mjs` ever regrowing a hardcoded literal for any of the ten.
- **`SKILL.md`'s and `README.md`'s command tables can no longer silently drift apart.** New `checkCommandTableDrift()` in `scripts/lint.mjs` fails if a command name appears in one and not the other.
- **`writing.md` and `docs/STYLE.md`'s no-fabrication doctrine now states its own enforcement strength accurately.** Both previously read as an absolute guarantee; `docs/decisions/0016`'s actual enforcement hard-fails only on a locked-span mismatch; dropped/added facts warn by default and only block if a project explicitly opts in via `check.hard_fail_on_dropped_fact`/`check.hard_fail_on_added_fact`. No behavior change, both files now say so.


A real drafting session produced two same-topic CTA lines that scored identically on the Human Score despite one reading noticeably more aggressive than the writer intended, since the score measures "reads AI-written," not "matches the writer's intended tone," two genuinely different questions. Rather than folding tone into the scored rule dictionary (which would have conflated those two claims into one number), this release adds tone as a new, non-scored dimension of the voice profile itself: "sound like a human" was never one target, and this makes "which type of human" something a voice can state, see [docs/decisions/0024](docs/decisions/0024-voice-register.md). The same shadow-drafting session then surfaced a second, unrelated gap: a clearfelt-writing-drafted post verbed "due diligence" into "diligences it" while paraphrasing, and the odd word choice measurably raised the document's vocabulary-diversity score, since MATTR rewards rarity, not naturalness. A general fix needs real infrastructure this repo hasn't taken on for anything else, so this release ships the cheap, evidence-first fix instead and defers the general case with the reasoning written down.

### Added

- **A `register:` field in voice profiles**, `neutral` (default) / `direct` / `warm`, read from a new `## Register` section in `.clearfelt-writing/voice-profile.md` or `.clearfelt-writing/voices/<name>.md`. Same precedence as "Sentence rhythm" (ADR 0021): an override file's own value wins if set, otherwise it inherits the base file's through `extends:`, otherwise `neutral`.
- **Two new word lists**, `rules/register/accusatory.md` and `rules/register/hedging.md`, loaded through a new `loadRegisterRules()` in `scripts/lib/rules.mjs`, entirely separate from `loadRules()`'s scored set. `register: warm` activates the accusatory list; `register: direct` activates the hedging list; `neutral` activates neither. Entries carry `source: editorial`, not a `docs/SOURCES.md` key: this is a curated tone categorization, not an AI-detection research claim, and `docs/SOURCES.md`'s citation requirement is explicitly scoped to `rules/antipatterns/` and `rules/banned_words/` only.
- **`registerCheck` field on `scripts/detect.mjs --mode report`**, present only when the resolved register isn't `neutral`. Never appears in `--mode score`'s compact payload and never reaches `computeScore`: a register mismatch doesn't change whether the score number means anything, unlike `scoreReliability` (docs/decisions/0023), so it stays out of the terse payload the write/rewrite loops iterate against.
- **`--register <value>` on `scripts/detect.mjs`**, a per-invocation override with the same precedence shape as `--exempt-repetition`: useful for testing without editing a voice file, though a voice profile is where a project states its persistent choice. An unrecognized value is a hard error at both the CLI and the voice-profile layer, never a silent fallback to neutral.
- Register hits bypass tier-2/tier-3 clustering suppression (`findHits(..., { includeSuppressed: true })`): that suppression exists to protect the score from an isolated legitimate word choice, and a register hit never reaches the score it protects, so applying it anyway silently hid a real, isolated mismatch (the exact one-word case that motivated this release).
- `reference/audit.md`, `reference/write.md`, and `reference/rewrite.md` updated to surface a fired `registerCheck` as a short, separate advisory note, never folded into the score explanation, never treated as something to loop toward resolving.
- `templates/voice-profile.example.md` documents the new `## Register` section.
- **`rules/antipatterns/corporate_neologisms.md`**, a new category catching nouns forced into verb slots with a pronoun object immediately after ("diligences it"), narrowly scoped so it never flags the legitimate noun use ("due diligence document") or a verb use without a pronoun object ("diligence a term sheet"). `source: clearfelt-writing-heuristic`, an observed pattern, not a research citation.
- **`tests/fixtures/word-naturalness-log.md`**, a plain running log (not scored, not wired into `scripts/eval.mjs`) of real word-choice cases like this one, so a future general detector, if one ever gets built, is built against accumulated evidence rather than a single anecdote.
- **A new "Feature G" entry in `docs/ROADMAP.md`**: general word-choice naturalness detection (n-gram surprisal or a verb-lemma dictionary), scoped and deliberately not built yet, with an explicit reopening condition (the hand-curated rule list becoming the actual bottleneck).

### Fixed

- `reference/audit.md`'s numbered flow had a gap in its own numbering (step 6 missing between 5 and 7, left over from a prior edit); filled by this release's new step rather than left as a cosmetic oddity.

## [0.6.0] - 2026-08-20

Closes one of the two features `docs/ROADMAP.md` deliberately deferred in 0.5.0 ("platform-scoped non-negotiables within one voice profile"), once a real integration turned the theoretical gap into an actual, observed conflict, see [docs/decisions/0021](docs/decisions/0021-platform-scoped-voice-inheritance.md) for the full reasoning. The same integration's first real shadow-mode comparison then surfaced a second, related gap: a published-quality post scoring below threshold purely because it deliberately repeated a phrase as a hook/CTA callback, a real device, not AI-model filler, see [docs/decisions/0022](docs/decisions/0022-repetition-exemptions.md). A subsequent CPO-lens review (market reach/generality, then ecosystem fit/trust) of this same working repo found the architecture solid but six real gaps between "well-engineered" and "generic enough for anyone," one code change and five documentation. All of it shipped together since nothing here was ever tagged or released separately.

### Added

- **A disclosed language-confidence warning**, `scoreReliability`/`languageConfidence`/`languageWarning` fields on `scripts/detect.mjs`'s report (both `--mode report` and `--mode score`, present only when it fires). `docs/RESEARCH.md` already discloses that non-native English writers are misflagged by this class of statistical detector; every signal in `scripts/lib/score.mjs` and every rule dictionary entry is English-only by construction, so a non-English document previously got a confident-looking, meaningless score with no disclosure. New `scripts/lib/language.mjs`, a cheap English-function-word-ratio heuristic, not a language detector or a translation feature. `reference/audit.md` and `reference/write.md` updated to surface it plainly, forward in the response, same placement `risk_tier: sensitive` already gets. See [docs/decisions/0023](docs/decisions/0023-language-scope-warning.md).
- **A "60-second start" section in `README.md`**, immediately after "Why": one command, no setup, no voice profile, showing a real score from a fresh file with no `.clearfelt-writing/` directory. The zero-config path already worked; it was just buried under a 20-bullet feature list. `reference/setup.md`'s wizard-rule section now surfaces the existing defaults-skip path as a first-class option instead of something a user had to already know to ask for.
- **An explicit "runs entirely on your machine" claim** in `README.md`: `scripts/detect.mjs` and everything it imports are genuinely zero-dependency, no network calls, verified from the code; this was true before and simply unstated.
- **An explicit responsible-use scope statement** in `README.md`: clearfelt-writing is for making your own writing sound like you, not for disguising AI-generated text as human-written where disclosure matters (academic submissions, journalism). Same spirit as `docs/ROADMAP.md`'s existing "clearfelt-writing viral" rejection, stated in the project's own words rather than left to be inferred.
- **A new "Feature F" entry in `docs/ROADMAP.md`**: a non-CLI delivery surface for non-technical writers, documented and deliberately not built, since it conflicts with `CLAUDE.md`'s standing "Claude Code only, v1" rule and is a different trust model than the current fully-local guarantee.
- **A lighter "Note" decision-record tier**, `docs/decisions/notes/`, for narrow, backward-compatible additions that don't change how existing pieces compose, so the full-ADR bar stays reserved for real architectural calls as adoption grows past a single user. See `docs/decisions/README.md`'s new "ADR vs Note" section.
- **`extends:` inheritance for multi-voice profiles.** A `.clearfelt-writing/voices/<name>.md` file can now start with a one-line `extends: <base-name>` directive, naming another file in the same directory to inherit from. One hop only, no chained inheritance: a base file that itself declares `extends:` is rejected with a plain error rather than silently walked further. Merge policy, resolved once in `scripts/lib/config.mjs`'s new `resolveVoiceChain()`: list sections ("Words I want to keep using," "Words to avoid," "Non-negotiables") union, the override file only ever adds to the base, never silently drops a base entry by omission; sentence rhythm overrides if the override file sets it, otherwise inherits the base's; personal calibration inherits the base's computed numbers unless the override file has its own complete calibration section, in which case it wins outright. `prompts/write_loop.xml` and `prompts/audit_loop.xml` updated so the agent follows the same policy for the sections `config.mjs` doesn't machine-parse.
- **`/clearfelt-writing setup` gains a platform-scoping path for multi-voice.** Asks whether `voice.mode: multi` is for multiple writers (the original flow, unchanged), multiple platforms for one writer (new), or both. The platform path always creates `general.md` first (no `extends:` line, the base every platform extends), then loops one platform at a time (a plain "add another platform?" yes/no after each), asking only what's genuinely different on that platform and writing `extends: general` automatically. Deliberately no hardcoded platform buttons in the picker (not even "LinkedIn"), only "General" as a structural option plus free-text `Other`, so the question stays reusable for any writer's actual platforms rather than overfitting to the project that motivated it, see `docs/decisions/0021`'s own note on applying the project's generality test to its own design.
- **`scripts/explain.mjs` reports voice-profile provenance through the inheritance chain**: new `extends`, `basePath`, `keptWordsFromBase`/`keptWordsFromOverride`, and `personalCalibrationSource` fields, so it's visible at a glance which file a resolved rule or calibration number actually came from, not just the flattened result.
- **`templates/voice-profile.example.md`** documents the `extends:` directive and merge policy at the top.
- **`--exempt-repetition <phrase>` on `scripts/detect.mjs`** (repeatable). Excludes a specifically named phrase from the repeated-phrase penalty (`trigramRepetitionRatio`/`repetitionPenalty`), for a phrase repeated on purpose (a hook/CTA callback, anaphora) rather than accidentally. Every other statistical signal (burstiness, vocabulary diversity, paragraph variety, wall-of-text) is unaffected. The report payload echoes back which phrases were exempted (`exemptRepetition`), present only when the flag was used, so a saved report discloses the exemption rather than hiding it.
- `scripts/lib/score.mjs`'s `trigramRepetitionRatio(text, exemptPhrases)` and `computeScore(text, hits, config, exemptPhrases)` both take the new optional parameter, defaulting to `[]`; existing callers see byte-identical behavior unchanged.
- `prompts/write_loop.xml` and `prompts/audit_loop.xml` also updated: when a candidate draft deliberately repeats a phrase as a device, the agent passes `--exempt-repetition` when scoring it, instead of either accepting an unearned low score or rewriting away a legitimate technique to chase a higher number.

### Changed

- `docs/ROADMAP.md`'s "Platform-scoped non-negotiables within one voice profile" entry removed (a decision made moves out of "deferred" into an ADR, per that file's own stated convention). A related, adjacent idea raised during the same integration, engagement/virality optimization, was evaluated against the same generality test and explicitly declined, documented as a new entry instead.
- Existing multi-voice users unaffected: a `.clearfelt-writing/voices/<name>.md` file with no `extends:` line resolves exactly as it did before this release, zero forced migration. `exemptPhrases` defaults to `[]` everywhere it was added, so a project that never passes `--exempt-repetition` sees byte-identical scoring to before.
- Nothing about existing scoring behavior changed for English text either: the new language-confidence fields are additive and only appear when they fire.

### Not built, and why

- Auto-detecting which repetition is intentional (so `--exempt-repetition` wouldn't need a human/agent to declare it) was considered and declined: there is no reliable, deterministic tell that separates a deliberate callback from accidental repetition from word patterns alone, the same false-confidence problem that already declined `docs/ROADMAP.md`'s Feature C.
- A voice-profile-level "recurring device" section (for a writer whose signature move is always anaphora, not just one document) stays undesigned until a real, evidenced recurring case shows up; every case in hand so far is one specific phrase in one specific document.
- Auto-detecting or scoring for "engagement"/"hook strength" more broadly was raised and declined for the same reason `docs/ROADMAP.md`'s Feature E already was: no deterministic proxy exists for it.

### Fixed

Nothing carried over from a bug this cycle; this release is additive only.

## [0.5.0] - 2026-08-13

Two new engine capabilities closing real, code-grounded gaps identified from a review of every content-generation use case clearfelt-writing was being asked to cover, plus a full push to literal 100% line/branch/function test coverage across the repo.

### Added

- **Personal calibration.** New `scripts/calibrate.mjs` computes a writer's own MATTR (vocabulary diversity), sentence-length burstiness, and paragraph-length variance from a writing sample or a directory of past drafts, reusing the same statistical functions `scripts/lib/score.mjs` already exports rather than adding new statistical code. `/clearfelt-writing setup` runs it automatically and stores the result in `.clearfelt-writing/voice-profile.md`'s new "Personal calibration (computed)" section; `scripts/lib/config.mjs`'s new `loadVoiceProfileCalibration()` reads it back and overrides `clearfelt-writing.config.md`'s generic, fixture-derived `vocabulary_diversity_baseline`, `burstiness_baseline`, and `paragraph_variety_baseline` for that project's scoring only. Strictly additive: a project that never runs it sees identical behavior to before. See `reference/setup.md`.
- **Hard, checkable constraints.** New `--max-chars`, `--max-words`, `--must-contain`, and `--must-not-contain` flags on `/clearfelt-writing rewrite` and `/clearfelt-writing write`, usable inline for a one-off limit or as a reusable named set at `.clearfelt-writing/constraints/<name>.md` (new `templates/constraints.example.md`), passed with `--constraints <name>`. `scripts/check.mjs` verifies every declared constraint against the actual candidate text after a scrub or draft pass, not a prompt-only instruction: a length overshoot hard-fails by default, `must_contain`/`must_not_contain` follow the same `check.hard_fail_on_constraint_violation` toggle pattern already used for dropped/added facts. `prompts/write_loop.xml` and `prompts/audit_loop.xml` pass an active constraint set into every scrub pass, the same way locked spans already are, so generation targets it directly instead of only being checked afterward. New `docs/ROADMAP.md` documents two related features considered and deliberately not built this cycle (a structural-variety check against a corpus, and platform-scoped non-negotiables within one voice profile), with the reasoning for each.

### Fixed

- **`scripts/check.mjs`'s blockquote-preservation check was permanently dead code.** `extractQuotes`' blockquote detection was always run on `stripExcludedRegions()`-stripped text, the same text passed to the other three fact extractors, but stripping blanks out blockquote lines specifically, so a dropped or added blockquote could never be detected. Fixed by extracting quotes from the untouched raw text instead, keeping the other three extractors on the stripped text as before.
- **Two real test-suite concurrency bugs**, both found while pushing test coverage: `node --test` runs separate test files concurrently by default, and multiple test files independently backing up, mutating, and restoring the same real shared files (`~/.clearfelt-writing/settings.md`, `tests/fixtures/.clearfelt-writing/`) raced on which process's "did this exist before" check ran when, occasionally corrupting the other file's restored state. Fixed with a new `tests/helpers/global-settings.mjs`, a cross-process lock (atomic directory creation) shared by every test file that touches either path.

### Changed

- **Line, branch, and function test coverage is now literal 100%** (`node --test --experimental-test-coverage`) across every script and library file in the repo, up from roughly 75% branch / 92% function at the start of this cycle. Closed by writing a real, honest test for every legitimately reachable branch (including several requiring new dependency-injection seams, like `scripts/hook.mjs`'s `runHookBody` now taking optional `readStdin`/`runDetect`/`state` parameters so its stdin-failure and malformed-output paths can be exercised directly) and by simplifying away a handful of defensive branches proven unreachable given the codebase's own invariants (a `mean === 0` guard in `burstinessScore`/`paragraphStructureScore` where `lengths` is always pre-filtered to positive values; a `trigrams.length === 0` guard already covered by an earlier `words.length < 3` check; a `contextFor` not-found branch where the search value always originates as a literal substring of the text being searched), each left with a comment explaining why the branch could never trigger rather than a contrived test forcing it to.

## [0.4.0] - 2026-08-13

Found entirely through dogfooding `/clearfelt-writing setup`, `/clearfelt-writing audit`, and `/clearfelt-writing explain` against a real test project after v0.3.0 shipped, plus a structured three-persona review (prose self-consistency, software engineering, agent-pipeline design) of the whole repo.

### Added (`/clearfelt-writing write`)

- **New `/clearfelt-writing write [seed]` command**, turning a short seed (a rough draft, a paragraph of notes, an idea pasted straight into the request) into a full first draft, instead of editing an already-substantial document the way `/clearfelt-writing rewrite` does. Driven by a new `prompts/write_loop.xml` (seed and interview, draft from seed, score and preserve), which reuses `/clearfelt-writing rewrite`'s scoring, preservation-checking, confirm-before-write gate, and voice-profile precedence rather than duplicating any of it, the only new logic is the interview, the draft-generation pass, and a narrowed no-fabrication check (against the seed and interview answers, since there's no source document). A short interview (at most 4 questions, same `AskUserQuestion` wizard pattern as `/clearfelt-writing setup`) resolves anything the seed doesn't already state. Length (`short`/`medium`/`long`) replaces intensity as write's one tuning axis, since there's nothing existing to decide how much of to touch; resolved the same way, `.clearfelt-writing/domain.md`'s new `preferred_length` field, then a saved global preference, then ask. Always writes to a new file, never overwrites the seed. New `reference/write.md`, new `## Write` section in `clearfelt-writing.config.md` (`length`, `write.ask_length`), new "Preferred length" section in `templates/domain.example.md`, new `/clearfelt-writing write` templates in `reference/output-format.md`, `scripts/explain.mjs` and its output template gained `preferredLength`. `scripts/pin.mjs`'s `VALID_COMMANDS` gained `write`.

### Added (`/clearfelt-writing setup`)

- **`/clearfelt-writing setup` now detects a project's own pre-existing voice or style document** (`voice.md`, `VOICE.md`, `docs/voice.md`, `docs/VOICE.md`, `STYLE.md`, `docs/STYLE.md`, or a path the user supplies directly if none of those match) and asks explicitly whether to keep it as the voice source or build a fresh profile from the usual interview, rather than silently ignoring it or overwriting it. If kept, only asks about whichever of the four working fields (words to keep, words to avoid, sentence rhythm, non-negotiables) the source file doesn't already cover, purely additive to what the file already says, never restating or overriding it. `.clearfelt-writing/voice-profile.md` opens with an explicit source note pointing back at the original file, since `scripts/lib/config.mjs`'s override lookup only ever reads `.clearfelt-writing/voice-profile.md` directly and does not follow a reference at runtime. The original file is only ever read, never written to, under any circumstance. See `reference/setup.md`.

### Fixed

- **A labeled fixture set and a real consistency measurement for the "qualitative signals" reasoning step** (`reference/audit.md`'s narrative idiosyncrasy, episodic grounding, cognitive friction, synonym cycling, admits real stakes), the one part of the scoring pipeline that previously had zero eval coverage. New `tests/fixtures/qualitative/` (4 fixtures) and `scripts/qualitative-eval.mjs`, which scores recorded judgment runs and reports pairwise agreement between them once two or more exist. Seeded with two real runs: 90% pairwise agreement, the one disagreement landing on synonym cycling, exactly the signal `reference/audit.md`'s own text already calls "the harder case."

- `clearfelt-writing.config.md` gained `## Humanize`, `## Voice`, and `## Readability` sections.
- `CONTRIBUTING.md`: noted that voice and domain profiles are project-scoped, not shared rule files, no `source:` field required.
- `docs/STYLE.md`: noted readability is tracked separately from AI-tell scoring.

### Fixed

- `loadConfig()` never parsed `clearfelt-writing.config.md`'s "Category severity weights" section, and `computeScore` looked up weights under a `weight_<category>` key that was never populated. Every category silently scored at a 1.0 multiplier regardless of what the config file said, since the skill's original bootstrap. Both are fixed: the section is now parsed, and `computeScore` reads weights by category name directly. Anyone who had customized a category weight will see their score change to reflect the setting they actually configured.
- **Single-word lexicon matching was exact-literal-form only.** A rule for "leverage" never caught "leveraging"; "seamless" never caught "seamlessly"; "synergy" never caught "synergies." Found via dogfooding: a real test document scored 100/100 at every humanize intensity while still containing four unflagged, unmistakably AI-sounding words. `scripts/detect.mjs` gained `inflectionPattern()`, a heuristic (not real stemming) covering silent-e drop before `-ing`/`-ed`, the common `-s`/`-es`/`-ed`/`-ing`/`-ly` suffix set, and consonant+y pluralization (`synergy` becomes `synergies`). Applies only to single-word rules; multi-word phrases are unaffected. Scores will drop for any text that was previously under-flagged because of this gap, this is a correctness fix, not a new false-positive source.
- Added `synergy`, `synergistic`, `paradigm shift`, and `paradigm-shattering` to `rules/banned_words/puffery_lexicon.md` (`source: clearfelt-writing-heuristic`), the two lexicon words the dogfooding test surfaced as missing entirely.

**Breaking:** `intensity`'s valid values changed from `conservative`/`aggressive` to `light_touch`/`balanced`/`full_rewrite`/`structural_rework`, called out explicitly per `docs/RELEASE.md`'s rule on config setting-name changes. Anyone who had `intensity: conservative` or `intensity: aggressive` set in `clearfelt-writing.config.md` or `~/.clearfelt-writing/settings.md` needs to update it to the new slug (`conservative` maps to `light_touch`, `aggressive` maps to `full_rewrite`).

- **Tiers redesigned so each one touches a genuinely larger scope, not just polishes harder.** Found via testing: `balanced`, `full_rewrite`, and `structural_rework` all scored identically on a real document because none of them were scoped to touch words tier-suppression had hidden from the scored report, only the same 4 flagged spans plus rhythm. `scripts/detect.mjs --mode scan <path>` is new: it returns every rule-dictionary occurrence with tier-suppression bypassed (tiering protects the *score* from single-legitimate-use false positives, it was never meant to protect what `/clearfelt-writing humanize` is allowed to edit). `balanced` and above now use it. Result on the test document: `light_touch` (42) to `balanced` (99) is now a real, earned 57-point jump instead of a tie. `full_rewrite` and `structural_rework` still land close to `balanced` once there's nothing left to deduct for, that's an honest consequence of the remaining differentiator being fine statistical polish, not a bug. See `reference/humanize.md`'s "Choosing an intensity" for the full per-tier scope.
- **Two new scoring signals: paragraph-length variety and a wall-of-text penalty.** Every existing statistical signal (burstiness, vocabulary diversity, trigram repetition) operates on a flattened sentence/word stream and was completely blind to paragraph structure, found when a `structural_rework` pass that only changed paragraph boundaries moved the score by exactly zero. New `paragraphStructureScore()` (same coefficient-of-variation approach as burstiness, one level up, Markdown headers excluded from the count) and a flat `wall_of_text_penalty` for a long document crammed into a single paragraph. New `clearfelt-writing.config.md` rows: `paragraph_variety_weight` (8), `wall_of_text_penalty` (15), `wall_of_text_sentence_threshold` (5).
- **Score breakdown surfaced in the actual output, not just the JSON.** `scripts/detect.mjs` was already computing and returning every component of the final score (rule-hit deduction, burstiness, vocabulary diversity, trigram repetition, paragraph variety, wall-of-text penalty) in its `breakdown` object, but `/clearfelt-writing audit` and `/clearfelt-writing humanize` never showed it, only the single final number. Two files landing on the same score looked like a bug with no way to tell why from the response alone. New "Score breakdown" table in both templates in `reference/output-format.md` (`/clearfelt-writing audit` shows one; `/clearfelt-writing humanize` shows a before/after pair), always shown, not just on request.
