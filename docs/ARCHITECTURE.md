# Architecture

One user-invocable skill, `clearfelt-writing`, with five commands underneath it (`audit`, `rewrite`, `write`, `explain`, `setup`), routed through `SKILL.md`. See `SKILL.md`'s Commands table and `reference/*.md` for the full behavior of each command. Full design rationale: [decisions/](decisions/).

- `SKILL.md`: thin router only. Frontmatter, one-paragraph pitch, Commands table, routing rules. Do not add full command walkthroughs here; they belong in `reference/*.md`. See [decisions/0026](decisions/0026-reference-file-per-command-split.md) for why behavior lives per-command and presentation is split out separately.
- `writing.md`: the editorial doctrine behind every rule and rewrite decision, what clearfelt-writing considers bad writing, what it always preserves, when it refuses to rewrite. System-level, not user-specific; see [decisions/0013](decisions/0013-writing-and-voice-doctrine.md). A rule or a `prompts/audit_loop.xml`/`prompts/write_loop.xml` instruction that contradicts this file is a bug in one of the two.
- `voice.md`: doctrine about the voice-profile *system* (precedence, what it will and won't override), not a data file. An individual's actual preferences live in `.clearfelt-writing/voice-profile.md` (or `.clearfelt-writing/voices/<name>.md`), never in this file.
- `reference/audit.md`, `reference/rewrite.md`, `reference/write.md`, `reference/explain.md`, `reference/setup.md`, `reference/hooks.md`: full behavior per command, loaded on demand.
- `scripts/detect.mjs`: thin CLI entrypoint (arg parsing, mode dispatch) over `scripts/lib/`. Zero external dependencies, Node stdlib only, on purpose (see [decisions/0001](decisions/0001-deterministic-scored-detection.md)). Never add an npm dependency anywhere under `scripts/`.
- `scripts/lib/config.mjs`, `scripts/lib/rules.mjs`, `scripts/lib/score.mjs`, `scripts/lib/report.mjs`: the actual scoring engine, split by responsibility (see [decisions/0027](decisions/0027-scripts-lib-module-boundary.md) for why the boundary falls exactly there) (config precedence and voice/domain overrides; rule-dictionary parsing and matching; statistical signals, readability, and the score formula; pattern/category summaries and the single-file orchestration `runFile` that ties the others together). `scripts/detect.mjs`, `scripts/check.mjs`, and `scripts/explain.mjs` all import from here rather than duplicating any of this logic. `detect.mjs --exempt-repetition <phrase>` (repeatable) excludes a specifically declared phrase from the repeated-phrase penalty, for a phrase repeated on purpose (a hook/CTA callback, anaphora) rather than accidentally; the score never tries to detect intent itself, see [decisions/0022](decisions/0022-repetition-exemptions.md).
- `scripts/hook.mjs`, `scripts/pin.mjs`: hook admin/runtime and shortcut-skill creation, adapted from the `impeccable` skill's equivalent scripts. See [decisions/0028](decisions/0028-hook-and-pin-adapted-from-impeccable.md).
- `scripts/check.mjs`: preservation checker, deterministically diffs a source file against a rewrite (or write) candidate for locked-span and factual-fingerprint mismatches, run by `/clearfelt-writing rewrite`'s and `/clearfelt-writing write`'s pipelines before the confirmation view. See [decisions/0016](decisions/0016-preservation-checker.md).
- `scripts/explain.mjs`: read-only, prints every currently-resolved config setting with its provenance (default/shipped/global), plus voice/domain/hook state, powering `/clearfelt-writing explain`.
- `scripts/eval.mjs`: lightweight sanity check of the scoring weights against the labeled fixtures in `tests/fixtures/eval/`, not full validation, see [decisions/0011](decisions/0011-deduction-cap-and-signal-rebalance.md).
- `scripts/qualitative-eval.mjs`: scores recorded judgment runs (`tests/fixtures/qualitative/runs/*.json`) against `tests/fixtures/qualitative/manifest.json`'s labels for `reference/audit.md`'s five "Qualitative signals," and reports pairwise agreement once two or more runs exist. Cannot produce a judgment itself, only score one already recorded, since these signals are a reasoning step this repo makes no API call to automate; see [decisions/0018](decisions/0018-multi-persona-review-fixes.md).
- `scripts/routing-eval.mjs`: same shape as `scripts/qualitative-eval.mjs`, scoring recorded judgment runs (`tests/fixtures/routing/runs/*.json`) against `tests/fixtures/routing/manifest.json`'s expected command for each request, checking how reliably `SKILL.md`'s Routing section dispatches. Cannot judge routing itself, only score a judgment already recorded, since which command a request routes to is a model-judgment call ([decisions/0019](decisions/0019-model-judged-command-routing.md)); see [decisions/notes/0001](decisions/notes/0001-routing-eval-harness.md).
- `scripts/lint.mjs`: repo-consistency checks (frontmatter, XML tag balance, rule-source completeness, config-to-code drift, config-defaults drift, `detect.mjs`/`check.mjs` output shape against `schemas/*-report.schema.json`, em-dash prohibition repo-wide). Zero dependencies, same rule as `detect.mjs`. Run before any PR, see [DEVELOP.md](DEVELOP.md).
- `tests/`: `node --test` regression suite for `scripts/detect.mjs`, run as a real subprocess against `tests/fixtures/`. Run this, `node scripts/eval.mjs`, and `node scripts/lint.mjs` before any PR that touches scoring, config, or rule files, see [DEVELOP.md](DEVELOP.md).
- `rules/antipatterns/*.md`, `rules/banned_words/*.md`: the rule dictionary, one small file per category. `rules/*.local.example.md`: templates for personal, gitignored overrides. Every bullet in the shared files carries a `source:` key resolved in `SOURCES.md` (see [decisions/0005](decisions/0005-sourced-rules.md)). Never add a shared rule without one.
- `clearfelt-writing.config.md`: every tunable, one Markdown file. Never introduce a second place to configure the same setting. This is skill-level (shared across every project using a given install), not per-project; project-level customization happens through the `.clearfelt-writing/` files below, not by adding a second config file.
- `prompts/audit_loop.xml`: the 3-pass rewrite pipeline. The one non-Markdown file in the repo, deliberately (see [decisions/0003](decisions/0003-xml-pipeline-format.md)).
- `prompts/write_loop.xml`: the 3-pass write pipeline (seed and interview, draft from seed, score and preserve), reusing `/clearfelt-writing rewrite`'s scoring and preservation-check machinery with a draft-generation pass in front instead of starting from existing prose. Same non-Markdown exception as `prompts/audit_loop.xml` above.
- `.clearfelt-writing/voice-profile.md` (or `.clearfelt-writing/voices/<name>.md` in multi-voice mode), `.clearfelt-writing/domain.md`: project-scoped, gitignored override files, consulted by `scripts/detect.mjs` before flagging a hit (see [decisions/0004](decisions/0004-no-fabrication-and-voice-precedence.md) and [decisions/0007](decisions/0007-multi-voice-and-domain-profiles.md)). Templates: `templates/voice-profile.example.md`, `templates/domain.example.md`. `domain.md`'s `risk_tier: sensitive` forces the confirm-before-write gate on and stops `/clearfelt-writing rewrite` from rewriting away hedges/qualifiers, regardless of other settings, see [decisions/0010](decisions/0010-risk-tier-and-test-suite.md). A `.clearfelt-writing/voices/<name>.md` file can start with a one-line `extends: <base-name>` directive to inherit from another file in the same directory, one hop only, resolved by `scripts/lib/config.mjs`'s `resolveVoiceChain()`, see [decisions/0021](decisions/0021-platform-scoped-voice-inheritance.md).
- `.clearfelt-writing/audit.log`: gitignored, machine-appended record of every `/clearfelt-writing rewrite` or `/clearfelt-writing write` write (timestamp, path, intensity or length, score delta, approval). The only durable record that a write happened; a single interactive confirmation doesn't survive past the terminal session on its own.
